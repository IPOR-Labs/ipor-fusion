# IPOR Fusion architecture map

A short map of the main contracts and how they call each other. For vault internals (fallback router, plugins,
storage) see [`contracts/vaults/README.md`](contracts/vaults/README.md). For the concepts in plain language see
[Architecture overview](https://ipor.io/docs/build-on-fusion/architecture-overview/general.md).

## Components

```
                    FusionFactory  (clones one full stack per vault)
                          │
        ┌─────────────────┼──────────────────────────────────────────┐
        ▼                 ▼                  ▼               ▼        ▼
 IporFusionAccess    PlasmaVault ───────► PriceOracle    Withdraw   RewardsClaim
 Manager (roles,     (ERC-4626)           Middleware     Manager    Manager
 timelocks)              │                (Manager)                 (+ rewards fuses)
        ▲                │ delegatecall
        │ restricted     ▼
        └──────── fuses (action fuses + balance fuses, one set per market)
                         │
                         ▼
                 external protocols (Aave, Morpho, Euler, Pendle, …)
```

## Call flows

### Alpha runs a strategy step

1. Alpha calls `PlasmaVault.execute(FuseAction[] calls)`. `FuseAction` is `{address fuse; bytes data}`.
2. The access manager checks `ALPHA_ROLE` (and any execution delay).
3. For each call the vault checks the fuse is added (`FusesLib.isFuseSupported`), reads `MARKET_ID`, and
   `delegatecall`s `fuse.data`. The fuse checks substrates and talks to the external protocol.
4. After the loop the vault calls each touched market's balance fuse (plus markets in its dependency graph),
   stores the new balances, and updates `totalAssets`.
5. Market limits and performance fee are applied. `ExecuteFinished` is emitted.

### User deposits and withdraws

1. `deposit`/`mint` are `restricted` (`WHITELIST_ROLE` until the vault is made public with `convertToPublicVault`).
   Assets stay in the vault as unallocated balance until the Alpha moves them.
2. `withdraw`/`redeem` pay from unallocated balance first. If short, the vault calls the instant-withdrawal fuses
   in the order set by `configureInstantWithdrawalFuses`.
3. For large or illiquid positions, users go through `WithdrawManager.requestShares` and later `redeemFromRequest`.

### Share price

`totalAssets()` = vault's own balance of the underlying + sum of stored market balances (from balance fuses,
converted from USD to the underlying) + `RewardsClaimManager.balanceOf()` if a rewards manager is set. Fee
calculations use the net value (minus unrealized management fee). Balances refresh on
`execute`, `updateMarketsBalances`, and through pre-hooks. Rules:
[General share price calculation rules](https://ipor.io/docs/build-on-fusion/developer-guide/general-share-price-calculation-rules.md).

## Storage and upgrades

- All vault and manager state uses ERC-7201 namespaced storage (`contracts/libraries/PlasmaVaultStorageLib.sol`,
  `contracts/**/**StorageLib.sol`). Fuses run in the vault's storage context through `delegatecall`.
- Vaults and managers are deployed as clones by `FusionFactory` and initialized with `proxyInitialize`.
- UUPS-upgradeable: `PriceOracleMiddleware`, `PriceOracleMiddlewareWithRoles`, `FuseWhitelist`, `FusionFactory`,
  the wrapped-vault factories and the price-feed factories.
- Slot regression tests: `test/libraries/FusionStorageSlotsTest.t.sol`, `test/libraries/PlasmaVaultStorageLibSlotTest.t.sol`.
